# Language-pack development

**English** | [한국어](LOCALIZATION.md)

Otter keeps the UI language and report language independent.

- The **UI language** is stored in the `appearance/uiLanguage` key in
  `QSettings` and is applied after the application restarts.
- New installations default to English (`en-US`). A previously selected locale
  takes precedence.
- The **report language** is `presentation.language` in the project's
  `report-config.json`, so it travels with the project. Built-in Markdown and
  PPT bundle output currently supports English (`en-US`) and Korean (`ko-KR`),
  and new projects default to English.
- Stored values such as severity, status, and evidence classification are never
  translated. Translation happens only at UI and error-output boundaries.

## Language-pack locations

Built-in packs live in `webpentestkit/locales/*.json`. User-installed packs are
discovered in the `languages` directory under Qt's application-data location.
During development, `OTTER_LANGUAGE_PATHS` can name additional directories
separated by `os.pathsep`.

Windows packaging must include `webpentestkit/locales` in the executable.

## File format

```json
{
  "schemaVersion": 1,
  "locale": "en-US",
  "name": "English",
  "fallback": "ko-KR",
  "messages": {
    "ui": {
      "nav.dashboard": "Dashboard",
      "sample.count": "Count: {count}"
    },
    "errors": {
      "PROJECT_NOT_OPEN": "Open a project first."
    }
  }
}
```

- Packs are UTF-8 JSON and may not exceed 1 MiB.
- Only `schemaVersion` 1 is currently accepted.
- `locale` must be a normalizable identifier such as `ko-KR` or `en-US`.
- When a key is missing from the configured `fallback`, Otter finally checks
  the built-in `ko-KR` pack.
- Use named message parameters such as `{count}` and `{item_id}`.
- Keep translation keys stable when wording changes. Do not use the displayed
  sentence itself as a key.

## Using translations in code

```python
from webpentestkit.localization import tr

label = tr("nav.dashboard", "대시보드")
count = tr("sample.count", "개수: {count}", count=3)
```

Business logic never compares translated text.

```python
combo.addItem(tr("status.confirmed", "확인됨"), "Confirmed")
status = combo.currentData()  # always Confirmed
```

`KitError` retains the existing Korean message as a fallback while also
providing a code and parameters.

```python
raise KitError(
    "항목을 찾을 수 없습니다.",
    code="ITEM_UNKNOWN",
    params={"item_id": item_id},
)
```

The GUI uses `localize_error()`, so it displays `errors.ITEM_UNKNOWN` from the
active pack when present. The CLI and logs may continue to use the original
error message.

## Rules for new screens

1. Pass every new user-visible message to `tr()` with a stable key and Korean
   fallback.
2. Do not translate JSON fields, IDs, enums, or filter comparison values.
3. Do not merge the UI language and report language into one setting.
4. Runtime retranslating of all widgets is not supported yet; tell users to
   restart after changing the UI language.
5. Never put customer data, paths, or credentials in a language pack.

## English translation workflow

English source translations are organized by feature in
`translations/en-US/*.json`. The stable key-based runtime pack is generated by
the build command.

```powershell
python tools/i18n.py wrap
python tools/i18n.py sync
python tools/i18n.py build
python tools/i18n.py audit
```

- `wrap` converts remaining Korean literals in Qt GUI files to `tr()` calls
  with stable generated keys. Run it once after adding new text.
- `sync` adds statically declared `tr()` defaults under `qt_gui/**/*.py`,
  `PRESENTATION_*` error defaults, and dynamically declared role/slot labels
  from `presentation_engine/contracts.py` to the Korean catalog.
- `build` combines semantic `keys`, legacy text-based `sources`, and `errors`
  under `translations/en-US` to generate `webpentestkit/locales/en-US.json`.
  Semantic key translations take precedence and existing English translations
  are preserved.
- `audit` recursively checks Qt GUI modules for missing keys, presentation error
  codes, contract/catalog mismatches, key differences between catalogs, Korean
  text left in the English pack, and placeholder mismatches.

Generated keys use a hash of the source wording. Do not arbitrarily change an
existing key when its translation or wording changes. Prefer meaningful manual
keys such as `nav.dashboard` for reused or domain-significant messages.

## Validation

```powershell
python tools/i18n.py audit
python -m unittest tests.test_localization -v
python -m unittest discover -s tests -v
```

New language packs need tests for fallback, parameter substitution, error-code
translation, and rendering at a 1024px viewport.
