# 계정 금고와 암호화 프로젝트 보안 설계

[English](SECURE_PROJECTS_EN.md) | **한국어**

## 보호 목표

계정 금고와 암호화 프로젝트는 노트북·외장 디스크·백업 파일을 분실하거나
프로젝트 폴더가 잠긴 상태로 유출됐을 때 고객 정보, 진단 계정과 증적의
기밀성과 무결성을 보호합니다.

다음 위협은 이 기능만으로 방어하지 않습니다.

- 프로젝트가 열린 상태의 악성코드, 키로거와 메모리 덤프
- 사용자가 표시하거나 클립보드로 복사한 비밀 값
- 평문으로 내보낸 보고서, PPT 자료와 증적 사본
- 운영체제 관리자 권한을 장악한 공격자

전체 디스크 암호화, 화면 잠금, 승인된 백업 저장소와 최소 권한 운영은 계속
필요합니다.

## 저장 경계

- 취약점 지식 DB에는 고객 계정과 비밀 값을 저장하지 않습니다.
- 평문 프로젝트도 `secrets/credentials.vault`의 계정 데이터는 항상
  인증 암호화합니다.
- `finding.json`에는 향후 `ACC-001` 같은 계정 참조만 저장하고 사용자명,
  비밀번호, 토큰과 개인키를 복사하지 않습니다.
- 보고서, PPT Export, 검증 결과와 오류 메시지는 비밀 값을 출력하지 않습니다.

## 계정 금고 형식 v2

금고에는 무작위 256비트 데이터 키가 있고, 계정 JSON 전체를 AES-256-GCM으로
암호화합니다. 사용자의 암호는 Argon2id로 256비트 키 암호화 키를 유도하는 데
사용하며 데이터 암호화 키만 감쌉니다. 별도의 무작위 256비트 복구키 슬롯도
같은 데이터 키를 감쌉니다.

공개 헤더에는 형식 버전, 무작위 컨테이너 ID, KDF salt와 비용 파라미터,
암호화된 데이터 키, payload nonce와 ciphertext만 저장합니다. 계정 ID,
대상, 사용자명과 계정 개수도 암호화된 payload 안에 둡니다.

v2 payload에는 단조 증가하는 `nextCredentialNumber`도 포함됩니다. 보관된 계정을
영구 삭제해도 이미 사용한 `ACC-###` ID는 다시 발급하지 않습니다. 기존 v1 금고는
잠금 해제할 때 현재 계정 ID의 최댓값으로 다음 번호를 계산하며, 이후 금고를 변경하면
v2 payload로 저장됩니다.

보관된 계정은 비밀 값 표시·수정·검증이 차단됩니다. 복구하면 보관 전 상태로 돌아가며,
영구 삭제는 금고가 열린 상태에서 보관된 계정에만 허용됩니다.

기본 Argon2id 파라미터는 메모리 64 MiB, 반복 3회, 병렬도 4이며 salt는
16바이트입니다. 파일에서 읽은 KDF 비용은 메모리 고갈 공격을 막기 위해
애플리케이션 상한을 검사한 뒤 사용합니다.

모든 AES-GCM 암호화에는 새 96비트 nonce를 생성하고 컨테이너 ID, 슬롯 ID와
형식 버전을 추가 인증 데이터로 결합합니다. 암호가 틀리거나 헤더·ciphertext가
변조되면 평문을 반환하지 않습니다.

## 수명주기

- 금고 생성 시 복구키를 한 번만 표시하고 별도 보관 확인을 요구합니다.
- 암호 변경은 데이터 전체가 아니라 데이터 키를 새 키로 다시 감쌉니다.
- 저장은 같은 폴더의 임시 파일을 완성한 뒤 `os.replace()`로 교체합니다.
- 동시에 열린 오래된 세션은 파일 지문 충돌을 감지하고 덮어쓰지 않습니다.
- 잠금 시 서비스가 보유한 키 버퍼와 복호화 payload 참조를 폐기합니다.

Python 런타임과 운영체제는 문자열·메모리 복사본의 완전한 즉시 삭제를
보장하지 않습니다. 자동 잠금은 노출 시간을 줄이는 방어이며 안전한 메모리나
전체 디스크 암호화를 대체하지 않습니다.

## 암호화 프로젝트 형식 v1

`ProjectStorage` 경계 아래에 기존 폴더 저장소와 `.wpkproj` 암호화 저장소가
동일한 `ProjectService`를 사용합니다. 프로젝트별 무작위 256비트 데이터 키를
Argon2id 암호 슬롯과 별도의 256비트 복구키 슬롯으로 감싸며, 프로젝트 아카이브
전체를 스트리밍 AES-256-GCM으로 인증 암호화합니다. 공개 헤더에는 고객명,
프로젝트명, 대상과 파일명이 포함되지 않습니다.

내부 아카이브는 압축하지 않은 ZIP으로 만들고 해제 전에 파일 수, 개별·전체 크기,
중복·대소문자 충돌, 절대·상위 경로, 심볼릭 링크를 검사합니다. 원본 폴더를
암호화할 때도 프로젝트 밖을 가리키는 경로와 심볼릭 링크를 거부합니다.

변경은 암호화 컨테이너와 같은 폴더에 후보 파일을 완성하고 동기화한 뒤
`os.replace()`로 게시합니다. 세션 전체에 sidecar 잠금을 유지하고 파일 크기와
수정 시각 충돌을 확인하므로 다른 프로세스가 연 컨테이너를 덮어쓰지 않습니다.
백업도 임시 파일에 복사한 뒤 SHA-256이 일치할 때만 새 경로에 게시합니다.

## 프로젝트와 금고 연결

암호화 프로젝트 데이터 키에서 HKDF-SHA256으로 금고 연결 전용 키를 유도합니다.
금고 자체 데이터 키는 이 연결 키로 한 번 더 감싸므로 프로젝트 암호가 바뀌어도
금고 데이터를 다시 암호화할 필요가 없습니다. 기존 평문 금고를 포함한 프로젝트는
금고 암호 또는 금고 복구키로 처음 한 번 연 뒤 프로젝트 키 슬롯을 추가합니다.

## 잠금과 임시 작업공간

현재 경로 기반 서비스와 호환하기 위해 잠금 해제된 프로젝트는 권한을 제한한 OS
임시 디렉터리에 전체 작업 트리를 복호화합니다. 변경 시 즉시 재봉인하고 정상 잠금,
앱 종료 또는 15분 유휴 자동 잠금 시 작업공간을 삭제하고 키 버퍼를 덮어씁니다.

프로세스 강제 종료 후 남은 임시 파일, 스왑·페이지 파일, 파일 시스템 저널과 메모리
복사본의 완전 삭제는 보장하지 않습니다. 따라서 이 형식은 BitLocker·FileVault,
OS 화면 잠금과 EDR을 대체하지 않습니다. 평문 Export와 보고서 Export도 별도로
승인된 위치에서 관리해야 합니다.
