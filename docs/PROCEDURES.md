# 재현 절차와 증적

## 설계 원칙

재현 절차와 증적은 서로 다른 수명주기를 가지므로 분리해서 저장합니다.

- `procedure.json`은 테스터가 수행한 단계와 단계 순서를 관리합니다.
- `evidence/evidence.json`은 파일, 설명, 민감도와 보고서 사용 승인을 관리합니다.
- 절차 단계는 파일 경로를 직접 저장하지 않고 `EVD-001` 형식의 증적 ID만 참조합니다.
- 하나의 증적을 여러 단계에서 재사용할 수 있으며 Export에서는 파일을 한 번만 복사합니다.

## GUI 사용

1. 취약점 화면에서 항목을 선택합니다.
2. **수정**을 누른 뒤 **재현 절차** 탭으로 이동합니다. 저장된 절차는 오른쪽 상세 패널에서 바로 확인할 수 있습니다.
3. 사전 조건을 작성하고 **+ 단계**로 단계를 추가합니다.
4. 단계 제목, 수행 내용, 예상 결과와 관찰 결과를 작성합니다.
5. 증적 목록에서 기존 EVD를 선택하거나 **+ 새 증적 추가**를 사용합니다.
6. **위**, **아래** 버튼으로 보고서 출력 순서를 정하고 저장합니다.

새 취약점을 작성하는 동안에는 절차 단계를 먼저 입력할 수 있지만 아직 취약점 ID가 없으므로 증적 연결은 비활성화됩니다. 한 번 저장한 뒤 다시 열면 기존 증적 연결과 새 증적 추가를 사용할 수 있습니다. 저장 시 기술 상세가 포함된 `finding.json`과 `procedure.json`이 함께 반영되며 어느 하나라도 실패하면 모두 이전 상태로 복구됩니다.

보고서에 포함하는 단계가 참조하는 증적은 증적 자체도 **보고서 포함**이어야 하며 민감 정보가 없어야 합니다. 검증에 실패하면 보고서와 PPT Export가 중단됩니다.

## 저장 구조

```json
{
  "schemaVersion": 1,
  "findingId": "WEB-01-001",
  "preconditions": "권한이 다른 테스트 계정 2개가 준비되어 있습니다.",
  "nextStepNumber": 3,
  "steps": [
    {
      "id": "STEP-001",
      "order": 10,
      "title": "일반 사용자로 로그인",
      "action": "계정 A로 로그인합니다.",
      "expectedResult": "계정 A의 데이터만 조회됩니다.",
      "observedResult": "",
      "evidence": [],
      "includeInReport": true
    },
    {
      "id": "STEP-002",
      "order": 20,
      "title": "객체 ID 변경",
      "action": "요청의 객체 ID를 계정 B의 값으로 바꿉니다.",
      "expectedResult": "요청이 거부됩니다.",
      "observedResult": "계정 B의 데이터가 반환됩니다.",
      "evidence": ["EVD-001"],
      "includeInReport": true
    }
  ],
  "updatedAt": "2026-07-15T12:27:14+09:00"
}
```

`STEP-###` ID는 한 번 발급되면 순서를 바꾸어도 유지됩니다. 삭제된 번호는 재사용하지 않습니다. 새 취약점에는 빈 `procedure.json`이 함께 생성됩니다.

## 보관과 Export

증적을 보관하면 연결된 절차 단계에서도 EVD 참조가 제거되고, 보관 메타데이터에 단계 ID가 기록됩니다. 복원할 때 해당 단계가 여전히 존재하면 참조도 복원됩니다.

PPT 번들은 기존 `finding-detail` 뒤에 보고서 포함 단계별 `finding-procedure` 슬라이드를 생성합니다. 각 단계에는 수행 내용, 예상·관찰 결과와 연결된 증적 메타데이터가 포함됩니다. 슬라이드당 두 개를 넘는 증적은 `finding-evidence` 또는 `finding-procedure-evidence` 연속 슬라이드로 모두 출력되고 파일은 한 번만 복사됩니다. 취약점별 Export 폴더에는 `procedure.json`, `technical-details.md`, 재현 절차와 기술 상세가 합성된 `summary.md`도 생성됩니다.

## 재검증 이력

재검증은 기존 절차를 복사한 독립 이력으로 저장합니다. 취약점 상세의 **+ 재검증 기록**에서 날짜, 담당자, 전체 결과, 조치 내용과 각 단계의 결과·관찰 내용·증적을 기록합니다. `Passed`는 취약점 상태를 `RetestPassed`, `Failed`는 `RetestFailed`로 연동하며 과거 이력은 덮어쓰지 않습니다. 보고서에는 `retests.md`, PPT에는 `finding-retest`와 필요한 연속 증적 슬라이드가 자동 생성됩니다.
