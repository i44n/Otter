# Otter 사용자 가이드

[English](USER_GUIDE_EN.md) | **한국어**

> [!WARNING]
> Otter `0.1.0b1`은 첫 공개 베타입니다. 중요한 프로젝트는 별도로 백업하고,
> 고객에게 전달하기 전 생성된 산출물을 반드시 사람이 검토하십시오.

Otter는 별도 서버 없이 로컬에서 실행되는 웹 취약점 프로젝트 관리 도구입니다. 고객별 프로젝트와 증적은 프로젝트 폴더에 저장되고, 재사용 가능한 표준 취약점 지식만 별도의 SQLite 데이터베이스에 저장됩니다.

Otter는 승인된 진단의 기록과 산출물 작성을 돕습니다. 대상을 자동 스캔하거나 공격을 실행하지 않습니다.

## 설치 및 첫 실행

Python 3.10 이상이 필요합니다. 저장소를 복제한 뒤 가상 환경에서 의존성을 설치하는 것을 권장합니다.

### Windows

```powershell
git clone https://github.com/Insu-Cho/Otter.git
cd Otter
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python .\otter.py gui
```

### macOS

```bash
git clone https://github.com/Insu-Cho/Otter.git
cd Otter
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 ./otter.py gui
```

## GUI 실행과 화면 구성

이미 의존성을 설치했다면 저장소 루트에서 다음 명령으로 실행합니다.

```powershell
python otter.py gui
```

| 영역 | 용도 |
| --- | --- |
| 대시보드 | 취약점 수, 심각도 분포, 산출 대상으로 선택했지만 증적이 없는 항목과 최근 변경 확인 |
| 진단 대상 | URL, 환경, 상태를 포함한 진단 범위 관리 |
| 취약점 | 검색·필터 표, 상세 내용, 재현 절차, 재검증과 연결 증적 관리 |
| 증적 | 이미지·HTTP·텍스트 증적과 모든 사용처 확인 |
| 계정·접속정보 | 암호화된 진단 계정과 토큰 관리 |
| 공용 라이브러리 > 취약점 라이브러리 | 모든 프로젝트에서 재사용할 공통 취약점 정보 관리 |
| 산출물 | 산출 준비 상태 확인, Markdown·CSV 생성, 프로젝트 PPT 생성·검토 |
| 공용 라이브러리 > PPT 템플릿 | 프로젝트와 독립적으로 회사 PPTX의 콘텐츠 연결과 슬라이드 순서 관리 |
| 보관함 | 보관된 대상·취약점·증적·계정 복구 또는 영구 삭제 |
| 설정 | UI 언어, 프로젝트 정보와 프로젝트 보호 관리 |

취약점 화면은 전체 너비의 검색·필터 표를 제공하고 행을 더블클릭하면 상세 화면으로 전환합니다. `목록으로`, Esc 또는 Alt+Left로 돌아가도 검색·정렬·선택 위치가 유지됩니다. 증적 화면도 전체 증적을 검색·필터·정렬 가능한 표로 보여주며, 행을 더블클릭하면 이미지 또는 HTTP·텍스트 미리보기와 모든 사용처를 확인할 수 있습니다. 파일 끌어 놓기도 지원합니다.

### 단축키

| 단축키 | 동작 |
| --- | --- |
| `Ctrl+O` | 평문 프로젝트 열기 |
| `Ctrl+Shift+O` | 암호화 프로젝트 열기 |
| `Ctrl+Shift+N` | 취약점 추가 |
| `Ctrl+K` | 취약점 검색으로 이동 |
| `Ctrl+L` | 열린 암호화 프로젝트 잠금 |
| `Esc` 또는 `Alt+Left` | 상세 화면에서 이전 목록으로 돌아가기 |

특정 프로젝트 또는 지식 DB를 지정할 수 있습니다.

```powershell
python otter.py gui `
  --project .\examples\generated\acme-shop\project `
  --knowledge-db .\my-knowledge.db
```

기본 지식 DB는 Windows에서 `%LOCALAPPDATA%\Otter\knowledge.db`, macOS와 기타 환경에서는 `~/.otter/knowledge.db`에 생성됩니다.

### 언어와 테마 변경

**설정**에서 UI 언어를 English 또는 한국어로 선택하고 저장한 뒤 애플리케이션을 다시 시작합니다. UI 언어와 자동 생성 문구 언어는 서로 독립적입니다. 자동 생성 문구 언어는 **산출물 > 기본 정보**에서 선택합니다. 상단의 다크 모드 토글 상태도 다음 실행까지 유지됩니다.

## 샘플 프로젝트 둘러보기

실제 고객 데이터 없이 전체 흐름을 확인하려면 ACME 가상 샘플을 생성합니다. 샘플은 `example.test` 호스트와 마스킹된 가상 증적만 사용합니다.

```powershell
python .\examples\create_sample.py --force
python .\examples\open_sample_gui.py
```

## 기본 작업 순서

1. `프로젝트 > 새 프로젝트`에서 프로젝트 폴더, ID, 이름과 고객명을 입력합니다.
2. **진단 대상**에서 대상 URL과 환경을 추가합니다.
3. **취약점 라이브러리**에서 템플릿을 선택하거나 취약점을 직접 추가합니다.
4. 실제 확인 내용에 맞춰 심각도, URL, 역할, 영향과 조치방안을 수정합니다.
5. 취약점 추가·수정 창의 **재현 절차** 탭에서 과정을 작성하고, **기술 상세** 탭에는 원인과 분석을 작성합니다. **결과·산출물** 탭의 결과 증적은 절차의 마지막 단계가 아니라 취약점의 최종 관찰 결과에 연결됩니다.
6. 증적 탭에서 파일을 `내부용`, `보고서 준비 완료`, `민감 원본`으로 분류하고 취약점 결과·기술 상세·절차·재검증에 필요한 EVD를 연결합니다. 행을 선택하면 현재 연결 위치가 표시되며, 각 연결별로 `연결 위치에 표시`, `증적 부록`, `첨부만 제공`, 설명과 순서를 정합니다. 같은 증적도 다른 연결 위치에서는 별도 설정을 가질 수 있습니다. 편집창에서 새로 추가한 증적은 전체 저장 전까지 프로젝트에 반영되지 않습니다.
7. 취약점 상세의 **+ 재검증 기록**에서 취약점 단위 결과와 검증 내용을 기록하고 기존 증적을 선택하거나 새 증적을 등록 후 연결합니다.
8. **산출물**에서 준비 상태와 문제를 확인하고 필요한 Markdown/CSV 문서·데이터를 생성합니다.
9. 프로젝트와 무관하게 **공용 라이브러리 > PPT 템플릿**에서 회사 양식을 준비합니다. 프로젝트 **산출물 > PPT 생성·검토**에서는 준비된 템플릿을 선택하고 자동 생성된 초안을 검토한 뒤 실제 PPTX를 생성합니다.

## 회사 템플릿으로 PPTX 생성

템플릿 준비와 프로젝트 산출은 분리되어 있습니다. **PPT 템플릿**에서는 상단의
`1 PPTX 가져오기 → 2 콘텐츠 연결 → 3 슬라이드 순서` 안내만 따라갑니다.
같은 위치를 다시 보여주는 탭 메뉴는 숨겨져 있어 단계 안내가 유일한 내비게이션입니다. 화면 오른쪽의
`설정 중·검토 필요·저장 필요·사용 가능` 표시는 작업 단계가 아니라 현재 준비 상태입니다.
완료된 단계는 초록색으로 유지되고, 현재 열어 본 단계는 별도의 파란 배경으로 표시됩니다.
열린 프로젝트의 **산출물 > PPT 생성·검토**에서는
`템플릿 선택 → PPT 초안 만들기 → 필요한 부분만 조정 → PPTX 생성`을 수행합니다.

1. **템플릿 관리**에서 회사 PPTX를 선택합니다. 파일을 고르면 즉시 분석하고 같은
   템플릿의 기존 콘텐츠 연결을 자동으로 찾습니다. 기존 연결이 있으면 첫 슬라이드
   유형까지 바로 표시되며, 없을 때만 **새 콘텐츠 연결 시작**을 사용합니다.
2. **콘텐츠 연결**에서 원본 슬라이드의 각 영역을 `제목`, `영향`, `절차 설명`,
   `증적 이미지` 같은 콘텐츠 필드에 연결합니다. 슬라이드 유형과 콘텐츠 필드는
   Otter가 제공하는 고정 목록이므로 사용자가 임의 예약어를 만들 필요가 없습니다.
   데이터 유형도 선택한 필드에 따라 자동 결정됩니다. `단계 번호`를 연결하면
   `1`, `01`, `1단계`, `STEP 1`, `STEP 01`, 원형 숫자, 한글 순서 또는
   `{number}` 예약 토큰을 한 번 사용하는 사용자 형식을 고르고 결과를 바로 미리볼 수
   있습니다. 같은 슬라이드 유형의 반복 절차 영역에는 선택한 형식이 자동으로 동일 적용됩니다.
   우측의 **슬라이드 콘텐츠 영역**과 **선택 영역의 콘텐츠 연결** 사이 경계는 위아래로
   끌어 높이를 조절할 수 있고, 조절한 비율은 다음 실행에도 유지됩니다. 기본 높이는
   콘텐츠 영역을 최소 6행까지 검토할 수 있도록 잡혀 있습니다.
3. `진단 절차` 슬라이드는 한 페이지가 담을 수 있는 절차 영역을 1~12개로 지정할 수
   있습니다. 절차 증적은 선택 사항이며 한 단계에 여러 개를 연결할 수도 있습니다.
   PPT에는 `보고서 준비 완료`이면서 `연결 위치에 표시`로 설정한 이미지만 사용됩니다.
   템플릿에는 실제로 한 페이지에 표시할 증적 수만큼 이미지 프레임을 연결합니다.
   `취약점 결과`는 별도 슬라이드 유형으로 연결하되 같은 물리적 디자인이면 기존
   연결을 복제해 콘텐츠 필드만 확인할 수 있습니다.
4. 텍스트 영역을 연결하면 도형 크기와 글꼴을 기준으로 수용량을 추정합니다.
   `짧음·보통·김` 같은 주관적 구분은 기본 화면에 노출하지 않으며, 실제 초안을
   만들 때 문자열 길이와 이미지 수용량을 다시 검사합니다. 페이지 유형 등 내부
   선택 조건은 **고급 매핑 설정**에서만 조정합니다.
5. **슬라이드 순서**에는 권장 순서가 자동으로 준비됩니다. 보통은 그대로 사용하고,
   회사 양식이 다른 순서를 요구할 때만 **순서 편집**을 열어 문서·취약점·부록의 슬라이드 유형을 조정합니다.
   마지막으로 **템플릿 저장**을 누르면 모든 프로젝트에서 사용할 수 있습니다.
6. **산출물 > PPT 생성·검토**에서 템플릿을 고르고 **산출 범위**를 정합니다.
   화면에는 현재 포함된 대상·취약점·증적 수가 바로 요약됩니다. 일부 대상만 포함하려면
   **대상 변경**을 눌러 체크박스로 선택합니다. 모든 대상을 선택하면 자동으로 전체 범위로
   정규화됩니다. 범위를 바꾸면 그 범위로 초안을 다시 만들어야 하므로
   이전 범위의 내용이 최종 PPT에 섞이지 않습니다. 그다음 **PPT 초안 만들기**를 누릅니다.
   Otter는 절차 텍스트와 표시 대상인 절차 증적 이미지가 영역별 수용량에 맞는지 확인하면서
   연속 절차를 묶습니다. 따라서 7개 절차를 `2·2·2·1`로 고정하지 않고 실제 데이터와
   템플릿에 따라 `2·1·1·2·1`처럼 배치할 수 있습니다.
7. 초안이 만들어진 뒤에만 슬라이드 목록과 **선택 슬라이드** 요약이 나타납니다.
   자동 배치와 다르게 보여야 하는 슬라이드에서만 **미세 조정 열기**를 누릅니다.
   대체 배치가 있을 때만 `슬라이드 배치`가, 증적이 있을 때만 이미지 설정이 보이며,
   `잘릴 때 남길 위치`는 `영역 채우기`에서만 나타납니다. 변경은 즉시 자동 저장됩니다.
8. 사전 검사에서 템플릿, 콘텐츠 연결, 포함 슬라이드, 매핑 검토와 출력 위치를
   확인한 뒤 **PPTX 생성**을 누릅니다. 결과 PPTX와 같은 위치에 렌더 매니페스트가
   생성됩니다. 다른 사람의 배치 설정을 이어서 작업하거나 현재 설정의 사본이 필요하면
   상단의 **다른 PPT 배치 가져오기** 또는 **PPT 배치 사본 내보내기**를 사용합니다.
   절차 슬라이드를 선택하면 오른쪽 **절차 배치** 영역에서 절차를 한 장씩 분리하거나
   다음 절차 슬라이드와 합칠 수 있습니다.

예를 들어 한 취약점에 절차 7개가 있고 두 단계는 증적이 없고 세 단계에 증적 2개,
한 단계에 증적 1개,
취약점 결과에 증적 1개가 있어도 각 이미지를 슬라이드에 일일이 지정할 필요가
없습니다. 증적을 해당 절차 단계 또는 취약점 결과에 한 번 연결하면 Planner가
선택 가능한 레이아웃 그룹 안에서 콘텐츠 필드별 글자 수·증적 수용량에 맞는 페이지 유형과
절차 묶음을 선택합니다.
증적이 용량을 넘을 때만 같은 항목의 연속 페이지를 추가하며, 절차가 모두 끝난 뒤
독립적인 결과 페이지를 둡니다.
같은 증적 자산을 여러 사용처에 연결해도 원본 파일은 한 번만 관리됩니다.

목록 표는 `Ctrl` 또는 `Shift`와 클릭으로 여러 행을 선택할 수 있습니다. 진단 대상,
취약점, 증적, 계정, 취약점 라이브러리, 보관함에서는 선택 개수와 일괄 작업이 표시됩니다.
취약점 라이브러리와 계정 목록은 실수로 작업하지 않도록 첫 행을 자동 선택하지 않습니다.
증적 ID는 취약점마다 `EVD-001`부터 시작하므로 전체 증적 표에서는
`취약점 ID / 증적 ID` 형태로 표시됩니다.
취약점 라이브러리는 프로젝트 보관함과 다른 공용 데이터이므로 별도 보관 단계를 두지
않습니다. 하나 또는 여러 항목을 선택해 **삭제**하면 한 번의 확인 후 라이브러리에서
제거됩니다. 이미 프로젝트에 복사된 취약점은 변경되지 않습니다.

템플릿 파일이 콘텐츠 연결 저장 후 바뀌면 라이브러리에 `템플릿 변경됨`으로 표시됩니다.
**변경된 템플릿 매핑 복구**는 이전 도형과 새 도형을 비교해 자동 복구, 검토 필요,
누락으로 분류합니다. 검토 항목이 남아 있는 동안에는 PPTX 생성을 차단하며,
**콘텐츠 연결**에서 해당 슬라이드 유형을 확인하고 갱신한 뒤 템플릿을 저장해야 합니다.

기존 Profile v1/v2/v3/v4는 자동으로 v5로 변환됩니다. 과거 `finding-detail`은
`finding-overview`로, `*-evidence` 역할은 해당 의미 역할의 `continuation`
Variant로 변환됩니다. 지원하지 않는 과거 슬롯은 삭제하지 않고 검토 항목으로
격리됩니다.

단계 번호 포맷터는 v5의 선택적 바인딩 속성이므로 기존 v5 프로필도 변경 없이
로드됩니다. 포맷터가 없는 기존 `stepNumber` 연결은 이전과 같이 숫자만 표시합니다.

CLI에서는 같은 엔진을 다음 순서로 사용할 수 있습니다.

```powershell
python otter.py presentation analyze-template --project PROJECT --template TEMPLATE.pptx --output ANALYSIS.json
python otter.py presentation create-profile --project PROJECT --template TEMPLATE.pptx --output PROFILE.json
python otter.py presentation plan --project PROJECT --profile PROFILE.json --output PLAN.json
python otter.py presentation render --project PROJECT --template TEMPLATE.pptx --profile PROFILE.json --plan PLAN.json --output REPORT.pptx
```

## 취약점 템플릿

템플릿은 취약점 설명, 기본 영향, 조치방안, CWE와 기본 심각도의 초안입니다. 실제 취약점에 적용할 때 문구가 프로젝트의 `finding.json`으로 복사됩니다.

```json
"template": {
  "id": "WPK-ACCESS-001",
  "version": 1
}
```

라이브러리 상세 화면에서는 템플릿을 직접 수정하거나 삭제할 수 있습니다. 템플릿을 수정하거나 삭제해도 이미 프로젝트에 복사된 취약점 문구는 바뀌지 않습니다. 심각도, 실제 영향과 조치방안은 대상 시스템 상황에 맞게 반드시 검토해야 합니다.

- **수정**은 현재 라이브러리 항목을 바로 갱신하며 비슷한 새 버전을 만들지 않습니다.
- **삭제**는 상세 화면 또는 다중 선택 작업에서 한 번 확인한 뒤 라이브러리에서 제거합니다.
- 이전 버전에서 보관해 두었던 라이브러리 항목은 업데이트 후 활성 목록으로 복원됩니다.
- 기본 시드는 라이브러리를 처음 만들 때만 추가되므로 모든 항목을 삭제한 뒤 앱을 다시 열어도 자동으로 되살아나지 않습니다.

### 취약점 라이브러리 가져오기와 내보내기

취약점 라이브러리 화면의 `라이브러리 내보내기`는 재사용 가능한 취약점 설명, 영향, 조치방안, CWE와 검토 정보를 하나의 JSON 번들로 저장합니다. 호환성을 위해 기존 번들에서 가져온 과거 버전이 있으면 함께 보존하지만, 일반 수정 작업은 새 버전을 만들지 않습니다. 고객명, 대상 URL, 프로젝트 취약점과 증적은 포함되지 않습니다.

`라이브러리 가져오기`로 다른 환경의 번들을 병합할 수 있습니다.

- 동일한 ID와 버전의 내용이 같으면 기존 버전을 유지합니다.
- 동일한 ID와 버전의 내용이 다르면 충돌 오류를 표시하고 아무것도 변경하지 않습니다.
- 번들에 여러 버전이 있으면 순서대로 병합하며 가져오기 도중 오류가 발생하면 원본 DB 전체를 그대로 유지합니다.
- 과거 번들의 `archived` 표시는 숨김 상태로 가져오지 않고 활성 항목으로 정규화합니다.
- 가져오기 전에 조직에서 신뢰하는 번들인지 확인하십시오.

## 증적 정책

- 모든 증적 파일은 `evidence/files/`에 저장하고 공개 상태는 파일 경로와 분리합니다.
- 증적 편집기의 **증적 정보**에는 파일·제목·유형·공개 상태처럼 증적 자체의 속성만 입력합니다. 취약점 본문·기술 상세·절차·재검증 연결은 별도의 **사용처·연결된 항목** 영역에서 관리합니다.
- 취약점의 기술 상세·절차·재검증 편집 화면에서는 증적 행을 선택해 현재 사용처의 캡션과 `본문`·`부록`·`첨부만` 배치를 바로 지정합니다. 이 변경은 상위 편집 창을 저장할 때 함께 반영되며 취소하면 저장되지 않습니다.
- 취약점 편집 중 증적을 추가하면 현재 기술 상세·절차·재검증에 자동 연결됩니다. 전체 증적 화면에서 추가하거나 파일을 끌어 놓을 때만 등록할 취약점을 명시적으로 선택하며, 취약점 본문 연결은 선택 사항입니다.
- `internal`은 내부 참고용, `report-ready`는 마스킹 검토가 끝난 산출물용, `sensitive`는 민감 원본입니다.
- 분류를 바꿔도 파일을 이동하지 않습니다. 원본과 마스킹본을 함께 관리할 때는 마스킹본의 `derivedFrom`으로 원본 EVD를 연결합니다.
- 보고서에는 `report-ready`인 연결 증적만 출력합니다. 내부용·민감 증적도 업무상 연결할 수 있지만 검증 경고가 표시되고 산출물에서는 제외됩니다.
- HTTP 요청·응답은 기술 상세 입력란에 다시 붙여 넣지 않고 `http-exchange`, `http-request`, `http-response` 증적을 기술 상세에 연결합니다.
- 증적을 보관하면 파일과 `links.json`의 모든 사용처가 함께 제거됩니다.
- 보관함에서 복구하면 원래 경로, 메타데이터와 아직 존재하는 사용처 참조가 복원됩니다.

## 진단 계정 금고

`계정 및 접속정보` 화면에서 금고를 만든 뒤 진단용 비밀번호, API 토큰,
세션 쿠키, 클라이언트 인증서와 SSH 키를 관리합니다. 계정은 `ACC-001` 형식으로
자동 번호가 부여되며 대상, 환경, 역할, 사용자명, 목적, 범위, 담당자, 만료일과
검증 시간을 함께 기록할 수 있습니다.

- 비밀 값과 사용자명을 포함한 금고 payload 전체가 암호화됩니다.
- 비밀 값은 보고서, PPT Export와 오류 메시지에 포함되지 않습니다.
- 비밀 값을 클립보드에 복사하면 값이 바뀌지 않은 경우 30초 뒤 지웁니다.
- 복구키는 생성 직후 한 번 표시되므로 프로젝트와 분리해 오프라인 보관합니다.
- 평문 프로젝트에서도 금고는 암호화되며, 15분간 입력이 없으면 금고만 잠깁니다.
- 암호화 프로젝트에서는 프로젝트 키에 연결되어 프로젝트 잠금 해제와 함께 금고도 열립니다.

평문 프로젝트에서 이미 만든 금고를 암호화 프로젝트로 변환한 경우 처음 한 번은
기존 금고 암호 또는 금고 복구키로 열어야 합니다. 성공하면 현재 암호화 프로젝트에
자동 연결되며 이후에는 프로젝트 암호 하나로 열 수 있습니다.

## 프로젝트 전체 암호화

계정 화면의 `프로젝트 암호화`는 기존 폴더를 삭제하거나 수정하지 않고 `.wpkproj`
복사본을 만듭니다. 복구키를 별도 보관하고 새 파일이 정상적으로 열리는지 확인한 뒤
조직의 보존 정책에 따라 원본을 직접 정리하십시오.

상단 `프로젝트 열기` 메뉴에서 암호화 프로젝트를 암호 또는 복구키로 열 수 있습니다.
열린 프로젝트는 변경할 때마다 즉시 재봉인되고, 15분 유휴 시 또는 `Ctrl+L` 사용 시
잠기며 임시 작업공간을 정리합니다. 프로젝트 암호는 계정 화면에서 변경할 수 있고
복구키는 그대로 유지됩니다.

`암호화 백업`은 현재 상태를 먼저 재봉인한 뒤 SHA-256으로 복사 무결성을 확인한
새 `.wpkproj` 파일을 만듭니다. 상단 `프로젝트 열기 > 암호화 백업 복원`은 백업을
새 경로로 원자적으로 복사합니다. 원본 파일을 덮어쓰지 않으며 복원본은 기존 암호나
복구키로 다시 열어 확인해야 합니다.

암호화 프로젝트가 열려 있는 동안에는 애플리케이션 전용 OS 임시 디렉터리에 평문
작업 트리가 존재합니다. 정상 잠금 시 삭제하지만 강제 종료, 페이지 파일과 관리자
권한 악성코드는 이 기능만으로 방어할 수 없습니다. BitLocker 또는 FileVault 같은
전체 디스크 암호화, OS 화면 잠금과 승인된 백업 저장소를 함께 사용하십시오.

## 보관과 복구

활성 데이터에서는 삭제 대신 보관을 사용합니다. 대상, 취약점, 증적 또는 계정을 선택한 뒤 보관 사유를 입력합니다. 대상·취약점·증적은 프로젝트의 `archive/` 폴더로 이동하고, 계정은 암호화 금고 안에서 `Archived` 상태로 전환됩니다.

대상을 보관하면 그 대상 아래의 취약점과 증적도 함께 보이지 않게 되며, 대상을 복구하면 함께 복원됩니다.

보관함에서는 다음 작업을 수행할 수 있습니다.

- **선택 항목 복구**: 원래 위치와 상태로 되돌립니다.
- **영구 삭제**: 항목 ID를 직접 입력해 확인한 뒤 복구할 수 없도록 제거합니다.
- 보관된 계정은 계정 금고가 열려 있을 때만 표시됩니다.
- 금고가 잠겨 있으면 보관함에 잠금 해제 안내가 표시되고 계정 메타데이터도 노출하지 않습니다.
- 영구 삭제된 계정의 ID는 다시 사용하지 않습니다.

영구 삭제는 되돌릴 수 없습니다. 대상이나 취약점에는 하위 증적이 포함될 수 있으므로 필요한 경우 먼저 암호화 백업을 생성하십시오.

## 데이터 스키마

현재 개발 버전은 현재 스키마로 생성한 프로젝트만 지원합니다. 이전 버전 또는 현재 프로그램보다 새로운 버전의 프로젝트는 파일을 수정하지 않고 열기를 거부합니다.

## 검증과 보고서

검증 오류가 있으면 보고서 및 PPT 번들 생성을 중단합니다. 경고만 있으면 결과를 생성하지만 최종 배포 전에 내용을 검토해야 합니다.

GUI의 검증, 보고서 생성과 PPT Export는 백그라운드에서 실행되며 동시에 두 작업을 실행하지 않습니다.

보고서 포함 증적은 개수 제한 없이 모두 Export됩니다. 화면 배치 용량을 넘으면 연속 증적 슬라이드가 자동으로 추가됩니다.

기술 상세 설명은 `finding.json.technicalDetails`, HTTP 원문과 사용처는 `evidence/evidence.json` 및 `evidence/links.json`, 재검증 이력은 `retests.json`이 원본입니다. `technical-details.md`와 `retests.md`는 공통 보고서 뷰에서 자동 생성되므로 직접 편집하지 않습니다.

상단의 **다크 모드** 토글은 선택 상태를 저장하므로 프로그램을 다시 실행해도 유지됩니다. 마우스와 키보드 Enter/Space로 조작할 수 있습니다.

## 데이터 백업

고객별 프로젝트 폴더 전체와 조직에서 수정한 SQLite 지식 DB를 함께 백업하십시오. 취약점 DB JSON 내보내기는 지식 콘텐츠를 다른 환경으로 옮기기 위한 교환 형식이며 SQLite 파일의 운영 백업을 완전히 대체하지는 않습니다. 지식 DB에는 고객명, 대상 URL, 취약점 인스턴스와 증적이 저장되지 않습니다.

## 문제 해결

- `ModuleNotFoundError`가 표시되면 가상 환경을 활성화하고 `python -m pip install -r requirements.txt`를 다시 실행합니다.
- 프로젝트가 열리지 않으면 `project.json`이 있는 프로젝트 루트를 선택했는지 확인합니다.
- 암호화 프로젝트의 암호를 잊었다면 생성 시 별도로 보관한 복구키를 사용합니다. 암호와 복구키를 모두 잃으면 복구할 수 없습니다.
- 산출물 생성이 중단되면 **산출물 > 문제 목록**에서 오류를 먼저 해결합니다. 경고는 생성을 막지 않지만 배포 전에 검토해야 합니다.
- 증적이 보고서에 나타나지 않으면 해당 증적이 취약점의 필요한 사용처에 연결되어 있고 공개 상태가 `report-ready`인지 확인합니다.
- 공개 이슈에는 고객명, 실제 URL, 계정, 토큰, 원본 증적을 첨부하지 마십시오. 보안 취약점 신고는 [SECURITY.md](../SECURITY.md)를 따릅니다.

구조와 위협 모델에 대한 자세한 설명은 [암호화 프로젝트 보안 설계](SECURE_PROJECTS.md)와 [재현 절차·증적 모델](PROCEDURES.md)을 참고하십시오.
