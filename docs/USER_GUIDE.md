# Otter 사용자 가이드

Otter는 별도 서버 없이 로컬에서 실행되는 웹 취약점 프로젝트 관리 도구입니다. 고객별 프로젝트와 증적은 프로젝트 폴더에 저장되고, 재사용 가능한 표준 취약점 지식만 별도의 SQLite 데이터베이스에 저장됩니다.

## GUI 실행

최초 한 번 PySide6 의존성을 설치합니다.

```powershell
python -m pip install -r requirements.txt
```

```powershell
python otter.py gui
```

GUI 왼쪽 탐색 메뉴는 워크스페이스(대시보드, 진단 대상, 취약점, 증적), 진단 자원(계정·접속정보, 취약점 라이브러리), 산출물(검증·보고서), 관리(보관함, 설정) 순서로 구성됩니다. 취약점 화면은 검색·필터·상세
패널을 한 화면에 제공하며, 증적 화면에는 파일을 끌어 놓아 추가할 수
있습니다. `Ctrl+O`는 프로젝트 열기, `Ctrl+Shift+N`은 취약점 추가,
`Ctrl+K`는 취약점 검색, `Ctrl+Shift+O`는 암호화 프로젝트 열기,
`Ctrl+L`은 열린 암호화 프로젝트 잠금으로 동작합니다.

특정 프로젝트 또는 지식 DB를 지정할 수 있습니다.

```powershell
python otter.py gui `
  --project .\examples\generated\acme-shop\project `
  --knowledge-db .\my-knowledge.db
```

기본 지식 DB는 Windows에서 `%LOCALAPPDATA%\Otter\knowledge.db`, macOS와 기타 환경에서는 `~/.otter/knowledge.db`에 생성됩니다.

## 기본 작업 순서

1. `프로젝트 > 새 프로젝트`에서 프로젝트 폴더, ID, 이름과 고객명을 입력합니다.
2. **진단 대상**에서 대상 URL과 환경을 추가합니다.
3. **취약점 라이브러리**에서 템플릿을 선택하거나 취약점을 직접 추가합니다.
4. 실제 확인 내용에 맞춰 심각도, URL, 역할, 영향과 조치방안을 수정합니다.
5. 취약점 추가·수정 창의 **재현 절차** 탭에서 과정을, **기술 상세** 탭에서 원인 분석과 HTTP 요청·응답을 작성합니다.
6. 증적 탭에서 마스킹된 보고서용 증적과 민감 원본 증적을 구분해 추가합니다.
7. 취약점 상세의 **+ 재검증 기록**에서 전체 및 단계별 검증 결과를 누적합니다.
8. **검증·보고서**에서 오류와 경고를 확인하고 Markdown/CSV 보고서와 PPT 작성용 번들을 생성합니다.

## 취약점 템플릿

템플릿은 취약점 설명, 기본 영향, 조치방안, CWE와 기본 심각도의 초안입니다. 실제 취약점에 적용할 때 문구가 프로젝트의 `finding.json`으로 복사됩니다.

```json
"template": {
  "id": "WPK-ACCESS-001",
  "version": 1
}
```

템플릿을 새 버전으로 수정해도 이미 작성된 프로젝트 문구는 자동으로 바뀌지 않습니다. 심각도, 실제 영향과 조치방안은 대상 시스템 상황에 맞게 반드시 검토해야 합니다.

### 취약점 DB 가져오기와 내보내기

취약점 지식DB 화면의 `DB 내보내기`는 현재 템플릿의 최신본뿐 아니라 모든 과거 버전을 하나의 JSON 번들로 저장합니다. 이 번들에는 재사용 가능한 취약점 설명, 영향, 조치방안, CWE와 검토 정보만 포함되며 고객명, 대상 URL, 프로젝트 취약점과 증적은 포함되지 않습니다.

`DB 가져오기`로 다른 환경의 번들을 병합할 수 있습니다.

- 동일한 ID와 버전의 내용이 같으면 기존 버전을 유지합니다.
- 동일한 ID와 버전의 내용이 다르면 충돌 오류를 표시하고 아무것도 변경하지 않습니다.
- 새 버전은 버전 순서대로 추가되며 가져오기 도중 오류가 발생하면 원본 DB 전체를 그대로 유지합니다.
- 가져오기 전에 조직에서 신뢰하는 번들인지 확인하십시오.

## 증적 정책

- 보고서용 증적은 `evidence/report/`에 저장합니다.
- 민감 원본 증적은 `evidence/raw/`에 저장합니다.
- 민감 증적은 보고서 포함으로 전환할 수 없습니다.
- 보고서에 사용할 파일은 인증정보와 개인정보를 마스킹한 별도 사본이어야 합니다.
- 증적을 보관하면 파일, `evidence.json`, 취약점의 PPT 증적 참조가 함께 변경됩니다.
- 보관함에서 복구하면 원래 경로와 메타데이터가 복원됩니다.

## 진단 계정 금고

`계정 및 접속정보` 화면에서 금고를 만든 뒤 진단용 비밀번호, API 토큰,
세션 쿠키, 클라이언트 인증서와 SSH 키를 관리합니다. 계정은 `ACC-001` 형식으로
자동 번호가 부여되며 대상, 환경, 역할, 사용자명, 목적, 범위, 담당자, 만료일과
검증 시간을 함께 기록할 수 있습니다.

- 비밀 값과 사용자명을 포함한 금고 payload 전체가 암호화됩니다.
- 비밀 값은 보고서, PPT Export와 오류 메시지에 포함되지 않습니다.
- 비밀 값을 클립보드에 복사하면 값이 바뀌지 않은 경우 30초 뒤 지웁니다.
- 복구키는 생성 직후 한 번 표시되므로 프로젝트와 분리해 오프라인 보관합니다.
- 평문 프로젝트에서도 금고는 암호화되며, 15분간 입력이 없으면 금고만 잠깁니다.
- 암호화 프로젝트에서는 프로젝트 키에 연결되어 프로젝트 잠금 해제와 함께 금고도 열립니다.

평문 프로젝트에서 이미 만든 금고를 암호화 프로젝트로 변환한 경우 처음 한 번은
기존 금고 암호 또는 금고 복구키로 열어야 합니다. 성공하면 현재 암호화 프로젝트에
자동 연결되며 이후에는 프로젝트 암호 하나로 열 수 있습니다.

## 프로젝트 전체 암호화

계정 화면의 `프로젝트 암호화`는 기존 폴더를 삭제하거나 수정하지 않고 `.wpkproj`
복사본을 만듭니다. 복구키를 별도 보관하고 새 파일이 정상적으로 열리는지 확인한 뒤
조직의 보존 정책에 따라 원본을 직접 정리하십시오.

상단 `프로젝트 열기` 메뉴에서 암호화 프로젝트를 암호 또는 복구키로 열 수 있습니다.
열린 프로젝트는 변경할 때마다 즉시 재봉인되고, 15분 유휴 시 또는 `Ctrl+L` 사용 시
잠기며 임시 작업공간을 정리합니다. 프로젝트 암호는 계정 화면에서 변경할 수 있고
복구키는 그대로 유지됩니다.

`암호화 백업`은 현재 상태를 먼저 재봉인한 뒤 SHA-256으로 복사 무결성을 확인한
새 `.wpkproj` 파일을 만듭니다. 상단 `프로젝트 열기 > 암호화 백업 복원`은 백업을
새 경로로 원자적으로 복사합니다. 원본 파일을 덮어쓰지 않으며 복원본은 기존 암호나
복구키로 다시 열어 확인해야 합니다.

암호화 프로젝트가 열려 있는 동안에는 애플리케이션 전용 OS 임시 디렉터리에 평문
작업 트리가 존재합니다. 정상 잠금 시 삭제하지만 강제 종료, 페이지 파일과 관리자
권한 악성코드는 이 기능만으로 방어할 수 없습니다. BitLocker 또는 FileVault 같은
전체 디스크 암호화, OS 화면 잠금과 승인된 백업 저장소를 함께 사용하십시오.

## 보관과 복구

활성 데이터에서는 삭제 대신 보관을 사용합니다. 대상, 취약점, 증적 또는 계정을 선택한 뒤 보관 사유를 입력합니다. 대상·취약점·증적은 프로젝트의 `archive/` 폴더로 이동하고, 계정은 암호화 금고 안에서 `Archived` 상태로 전환됩니다.

대상을 보관하면 그 대상 아래의 취약점과 증적도 함께 보이지 않게 되며, 대상을 복구하면 함께 복원됩니다.

보관함에서는 다음 작업을 수행할 수 있습니다.

- **선택 항목 복구**: 원래 위치와 상태로 되돌립니다.
- **영구 삭제**: 항목 ID를 직접 입력해 확인한 뒤 복구할 수 없도록 제거합니다.
- 보관된 계정은 계정 금고가 열려 있을 때만 표시됩니다.
- 금고가 잠겨 있으면 보관함에 잠금 해제 안내가 표시되고 계정 메타데이터도 노출하지 않습니다.
- 영구 삭제된 계정의 ID는 다시 사용하지 않습니다.

영구 삭제는 되돌릴 수 없습니다. 대상이나 취약점에는 하위 증적이 포함될 수 있으므로 필요한 경우 먼저 암호화 백업을 생성하십시오.

## 데이터 마이그레이션

이전 스키마 프로젝트를 열면 마이그레이션 필요 오류가 표시됩니다.

```powershell
python otter.py migrate --project .\PROJECT
```

마이그레이션 전에 JSON 문서가 `archive/migrations/`에 자동 백업됩니다. 현재 프로그램보다 새로운 스키마의 프로젝트는 수정하지 않고 열기를 거부합니다.

## 검증과 보고서

검증 오류가 있으면 보고서 및 PPT 번들 생성을 중단합니다. 경고만 있으면 결과를 생성하지만 최종 배포 전에 내용을 검토해야 합니다.

GUI의 검증, 보고서 생성과 PPT Export는 백그라운드에서 실행되며 동시에 두 작업을 실행하지 않습니다.

보고서 포함 증적은 개수 제한 없이 모두 Export됩니다. 화면 배치 용량을 넘으면 연속 증적 슬라이드가 자동으로 추가됩니다.

기술 상세는 `finding.json.technicalDetails`, 재검증 이력은 취약점 폴더의 `retests.json`이 원본입니다. `technical-details.md`와 `retests.md`는 보고서 또는 PPT 번들을 만들 때 자동 생성되므로 직접 편집하지 않습니다.

상단의 **다크 모드** 토글은 선택 상태를 저장하므로 프로그램을 다시 실행해도 유지됩니다. 마우스와 키보드 Enter/Space로 조작할 수 있습니다.

## 데이터 백업

고객별 프로젝트 폴더 전체와 조직에서 수정한 SQLite 지식 DB를 함께 백업하십시오. 취약점 DB JSON 내보내기는 지식 콘텐츠를 다른 환경으로 옮기기 위한 교환 형식이며 SQLite 파일의 운영 백업을 완전히 대체하지는 않습니다. 지식 DB에는 고객명, 대상 URL, 취약점 인스턴스와 증적이 저장되지 않습니다.
